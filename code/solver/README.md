# solver：正式测试程序

## 一个文件：`官方测试_策略B.py`

对接官方模拟器的**正式测试主程序**，只依赖 Python 3 标准库，不 import 仓库里的任何其他文件。
策略是**策略 B**：问题三用方案四，问题四用方案七。

```powershell
# 0) 离线自检：只验证覆盖网证书，不连接模拟器（随时可跑）
python code\solver\官方测试_策略B.py --selfcheck

# 1) 正式测试：先在模拟器里登录、开始测试、等界面显示接口就绪，再运行
python code\solver\官方测试_策略B.py --problem 3 --robot-id 你的参赛队号
python code\solver\官方测试_策略B.py --problem 4 --robot-id 你的参赛队号
```

常用可选参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--base` | `http://127.0.0.1:2026` | 模拟器地址；改过端口才需要改 |
| `--timeout` | 5 | 单次 HTTP 超时秒数 |
| `--reserve` | 25 | 为 `/exit` 与写日志预留的现实秒数 |
| `--retries` | 4 | 网络故障时按同一 `request_id` 原样重放的次数 |
| `--net` | `auto` | 问题四覆盖网；`auto` 先用方案七 25 点网，自检不过依次退回 |
| `--log` | 按时间生成 | 动作日志（JSONL），同时写 `*.summary.json` |
| `--quick-check` | 关 | 跳过覆盖网稠密复验，只做解析证书（启动快 0.2 s） |

**没有给 `--problem` 和 `--robot-id` 时程序拒绝运行**，不会误连官方服务。

拿不准这一局是问题三还是问题四时，用 `--problem 4`：25 点三角网对全向源同样成立，
只是比八点网慢（本地对照约 380 vs 280 s/源）。反过来不成立——八点环网**不保证**发现定向源。

### 上场前三分钟检查单

1. `python code\solver\官方测试_策略B.py --selfcheck` 三张网都显示「通过」。
2. `--robot-id` 与模拟器界面上当前登录的参赛队号**逐字节一致**（含大小写与横杠）。
3. 模拟器端口若改过，跟上 `--base http://127.0.0.1:端口`。
4. 等界面显示机器狗接口就绪（5 秒倒计时结束）再回车，倒计时期间连接会直接失败。
5. 跑完把 `官方测试日志_问题X_*.jsonl` 与同名 `.summary.json` 收进支撑材料，官方加密日志保持原文件名。

## 客户端守住的协议要点（附件2）

- 路径、字段、编码、频道与坐标范围逐条校验；`Content-Type: application/json; charset=utf-8`。
- **串行单未决动作**：收到完整响应才发下一个动作，绝不并发。
- **同时检查 HTTP 状态与 `accepted`**；`accepted=false` 的 `virtual_time_s=0` 不当作当前虚拟时刻。
- 每个新动作一个新 `request_id`（`m-序号` / `c-序号`）；**只有超时、连接中断、响应非 JSON 时**才复用
  原请求体与原 `request_id` 原样重放，服务端按幂等返回首次响应，不重复移动、计时或清除。
- 409 / 429 / 5xx 不占用幂等键，按同 ID 同内容重发；400 / 404 / 405 / 413 / 415 与
  `200+accepted=false` 直接停机保留现场。
- 用 `/enter` 返回的 `remaining_real_duration_s` 加单调时钟管理现实截止时间，留 `--reserve` 秒收尾。
- 本地按附件2 §4 复算虚拟时间并与模拟器返回值对账，小结里给出 `virtual_time_drift_s`。
- 每条请求与响应写 JSONL 日志；结束写 `*.summary.json`（清除频道、虚拟时间、时间分解、重试次数）。

## 三层保证

1. **覆盖证书**：问题三 8 点正八边形覆盖半径 974.26 m < 1000 m；问题四 25 点非规则三角网，
   启动前自检「与圆盘相交的三角形三边 ≤1000 m + 凸包包住 1800 m 圆盘」并稠密复验最大方位间隔 < 180°，
   自检不过依次退回 NET4_V6（27 点）与 h=950 规则格网（27 点）。
2. **计数提前停**：已清除 + 已发现达 16 即停覆盖（题目保证总数 ≤16、每频道至多一个源）。
3. **有限兜底**：局部控制器失败进入 75×3=225 格清除网；若算法层整体抛异常，主程序再对
   「拿到过示向度但未清除」的频道逐个执行同一张兜底网，然后才 `/exit`。
