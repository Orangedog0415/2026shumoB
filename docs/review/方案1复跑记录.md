## 2. 压力测试：保证是否成立、时间是否符合预计

脚本：`code/experiments/压力测试.py`，输出在 `code/experiments/results/`。共 960 局，用固定种子，重复运行结果完全一致。

- 场景：问题三（全向）与问题四（混合，65% 定向）。
- 源数：N=10/13/16。
- 5 种误差模型：交接用的空间正弦场；每点独立的均匀误差；恒为 +1°；恒为 −1°；每点独立随机取 ±1°。
- 两种接收半径：[1000,1500] 内随机；全部取下限 1000 m。

## 3. 与预计的对照

| 预计来源 | 预计 | 实测 | 结论 |

| 文档 §9.1：26 局、18.39% | 见上表 | 复现，仅 3 局有平台浮点差 | 符合 |
| 审查 §2.1：时间主要花在移动 | 约 80–85% | 76–86% | 符合 |
| 审查 §2.2：大量源进入兜底 | 55% / 69% | 问题三 36–82%，问题四 45–76% | 符合，边界源尤其多 |

**平均定位清除时间的直观量级**：问题三每源约 7–8 分钟（虚拟时间），问题四每源约 17–18 分钟。
每源时间随 N 增大明显下降：覆盖扫描是固定成本，被更多的源分摊；问题四 N=16 时清满 16 个即可提前退出。
所以正式测试的“平均定位清除时间”受案例的 N 影响很大，论文里比较策略时应按 N 分组。
