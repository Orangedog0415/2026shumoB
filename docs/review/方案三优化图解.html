核心规则

什么时候顺路去清：一个椭圆

机器狗在覆盖点 A，下一站是 B。去清一个源 C 再到 B，比直接去 B 多走 |AC| + |CB| − |AB|。要求这段绕行不超过 x，等价于 C 落在以 A、B 为焦点的椭圆里。x 越大椭圆越胖。第二个条件是 r_ok：源的可能区域够小（半径 ≤ 150 m），去了才不用在现场慢慢找。

最大的一步是第一步：不再“发现即去”，而是每个点扫完、在后面的覆盖点顺带补测、最后集中清除。问题三靠这一步就省了约 100 s/源。问题四最大的收益来自格网变稀。

参数

x 取多大，r_ok 要不要

r_ok 必须有

不设 r_ok 时，x 越大越糟：机器狗会跑去清一个只知道方向的源，到了还得现场慢慢找。设 r_ok=150 m 后，曲线在很宽的范围内都很平。

x 可以再小

换成正八边形之后，问题三的最优点移到 x≈300 m（326 s/源），比交接材料里的默认值 600 m（336 s/源）再快约 3%；问题四在 300–800 m 之间几乎一样。建议把默认 x 改为 300 m。

顺带补测不能关

覆盖点上顺带测已发现源的方位，关掉后问题三升到 575 s/源、问题四升到 1085 s/源，比方案一还慢。推迟清除之所以划算，全靠后面的覆盖点替它交会定位。

要注意

方案三不是处处更快

问题四 N=16

方案一“发现即清”，清满 16 个就能提前收工，不必走完所有格点；方案三要等覆盖走完才集中清，于是 N=16 时平均 498 → 590 s/源，反而变慢。我试过“发现 16 个就停止覆盖”，结果更慢（问题三 336 → 363，问题四 745 → 755），因为剩下的源少了后续覆盖点的方位，定位变难。这里还有优化空间。

问题四仍有 8 局更慢

多数是定向源：后续覆盖点在它背后测不到，补测没信号，只能多走或兜底。

仿真≠模拟器

所有数字来自本地仿真和交接脚本的误差模型。x、r_ok、补测夹角等参数要在官方演练里再确认一次。
